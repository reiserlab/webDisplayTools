# Demo 2026-11-13: the arena side on the station PC

This branch (`demo/2026-11-13`) is one checkout with everything the arena side needs for the
arena + robot demo. It is `main` plus two branches that are not released yet:

- `feat/studio-remote-control` (PR 295): Arena Studio's remote-control mode.
- `feat/optomotor-open-loop-oscillation`: the two demo protocols and their pattern generator.

Use it only for the demo. It is not a release.

## Where things are

| What | Where |
|---|---|
| Walking protocol (open loop, then FicTrac closed loop, 4 min) | `protocols/g6_optomotor_osc_walking.yaml` |
| Flight protocol (open loop only, 4 min) | `protocols/g6_optomotor_osc_flight.yaml` |
| Pattern generator | `scripts/make-optomotor-osc-patterns.js` |
| Patterns (8 files, about 20 MB, not in git) | `protocols/g6_optomotor_osc_patterns/` after step 2 |
| Check of a run from its run log | `scripts/optomotor-oscillation-check.py` |
| Remote control: messages, client, bench check | `docs/development/studio-remote-control.md`, `rig/nodes/studio_remote.py` |
| Arena graph on Lyrical: install and launch | `rig/LYRICAL-BENCH.md` |
| Arena dashboard layout | `rig/foxglove/arena-rig.json` |

## Steps

1. Get the branch.

   ```
   git clone https://github.com/reiserlab/webDisplayTools
   cd webDisplayTools
   git checkout demo/2026-11-13
   ```

2. Build the patterns. The defaults are for the G6 2×10 arena with the fly facing the center of
   panel column 3, the same as ww18.

   ```
   pixi run node scripts/make-optomotor-osc-patterns.js
   ```

3. Install the arena graph (once). Do not run `pixi update`.

   ```
   cd rig
   pixi install --locked -e lyrical
   ```

4. Start the arena graph. The station launcher owns the Zenoh router, so start the station
   first and give the arena side `--no-router`.

   ```
   pixi run -e lyrical rig -- --no-router
   ```

   This starts the FicTrac adapter (UDP 60000) and the gateway (`ws://localhost:8765`).

5. Serve Arena Studio from this checkout (repo root) and open it in Chrome.

   ```
   python .claude\nocache-server.py 8092
   ```

   Open `http://localhost:8092/arena_studio.html` and connect the arena.

6. Upload the patterns: Console → Patterns → Add ▾ → local folder →
   `protocols/g6_optomotor_osc_patterns`. Arena Studio finds patterns by name. Do not run while
   the Run view shows a "not on the SD by name" warning.

7. Firmware check (see below), then a first run of the flight protocol from the Run view, with
   no fly.

8. Remote control: Run view → **Remote control** (or open the page with `?remote=1`). The
   sequence script then sends the walking file for the walking run and the flight file for the
   flight run. From a terminal, the same thing by hand:

   ```
   cd rig
   pixi run -e lyrical remote -- run ..\protocols\g6_optomotor_osc_flight.yaml
   ```

## Firmware check

The protocols were tested on the ww18 arena on 2026-11-12. An arena with older firmware can
differ in pattern upload, in finding patterns by name, and in playback of long GS16 patterns
(750 frames at 150 frames/s).

1. Note the firmware version: Arena Studio shows it when the arena connects, and the run log
   stores it as `controller_firmware`. Send it to Michael to compare with ww18.
2. Run the flight protocol once from the Run view, with no fly. Watch that each 20 s trial
   oscillates smoothly, with a turnaround every 2.5 s.
3. Check the run log:

   ```
   pixi run python scripts/optomotor-oscillation-check.py <run log .jsonl.gz>
   ```

   Pass: `PASS`, with every open-loop trial at 150 frames/s and no skipped frame.
4. If the upload, the name lookup or the check fails, stop and report the message. Do not
   change the protocol files.

## What each protocol needs

- **Flight:** the arena only. No FicTrac, no gateway.
- **Walking:** the gateway on `ws://localhost:8765` and FicTrac sending on UDP 60000. The last
  2 minutes are closed loop.
